# Mission-Control 0.16.2

## Что исправлено

С модулем 0.16.1 консоль в режиме полёта не спала: через 1–2 с после ухода в сон её будила линия Bluetooth (событие
PMC `BtWakeAp`, бит 20 `WAKE2_STATUS`), примерно через 12 с HOS усыплял её снова, и так всю ночь — батарея садилась
как при работе. Без режима полёта сон работал.

Проверка на OLED (HOS 23.0, Atmosphère 1.12.0):

| Что стоит | Сон в режиме полёта |
|---|---|
| без Mission Control | спит |
| только патчи bluetooth/btm, процесс выключен | спит |
| процесс 0.16.1 | петля, будит `BtWakeAp` |
| 0.16.1, пересобранный без изменений | код побайтно тот же — петля |
| 0.16.2 | спит, будит только кнопка питания |

## Изменения

- `GetEventInfo`, `GetHidEventInfo`, `GetBleManagedEventInfo` отдавали клиенту столько байт, сколько он попросил,
  из события фиксированного размера — за его пределами клиент получал соседние глобальные переменные, и результат
  менялся от сборки к сборке. Теперь копируется не больше нашего буфера, остаток — нули.
- Журнал сна `sdmc:/config/MissionControl/sleep_trace.log`: запросы psc, InitializeBluetooth/EnableBluetooth,
  сколько каждое событие ждало чтения и какой буфер просит каждый клиент. Пишет отдельный поток раз в секунду
  (не во время ухода в сон), файл начинается заново после 256 КБ. Если петля сна вернётся — этот журнал и строка
  `[sleep] разбудил:` из журнала Ryazha-clk покажут причину.

Патчи IPS (bluetooth, btm, hid) не менялись.

## Установка

Распакуйте `MissionControl-0.16.2.zip` в корень SD-карты с заменой файлов и полностью перезагрузите Switch.
На HOS 23.0.0 нужна Atmosphère >= 1.12.0. Существующий `missioncontrol.ini` сохраняется.
