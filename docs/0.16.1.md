# Mission-Control 0.16.1

## Изменения

Исходники обновлены до MissionControl 0.16.0, коммит
`71bbe2d4e97d618775b5a3e2f91bfeaf52d8b75e`, с поддержкой HOS 23.0.0.

В upstream обработчик `SwitchController::ModifyHidCommandInputReport`
перезаписывал 12 байт ответа SPI-read по адресу `0x6050`, если язык системы
равнялся `SetLanguage_RU` (10). Корпус подменялся на `#FFD700`, а кнопки и
рукоятки — на `#0057B7`. В этом форке блок удалён: настоящие Joy-Con и Pro
Controller возвращают цвета, записанные в их памяти, при любом языке системы.
EEPROM контроллеров не переписывается.

Обновление кнопок, стиков и поддержка эмулированных Bluetooth-контроллеров
сохранены. Отдельных таблиц цветов для сторонних контроллеров этот релиз
не добавляет: используются штатные данные актуального upstream.

Старые скрипты публикации и автоматического sync заменены ручным workflow
сборки. Временные ветки sync удалены после публикации обновлённого main.

## Установка

Распакуйте `MissionControl-0.16.1.zip` в корень SD-карты с заменой файлов.
Полностью перезагрузите Switch и переподключите Joy-Con. На HOS 23.0.0
используйте Atmosphère >= 1.12.0. Существующий `missioncontrol.ini` сохраняется;
архив содержит только шаблон конфигурации.

## Сборка

```sh
git clone --recurse-submodules https://github.com/Dimasick-git/Mission-Control.git
cd Mission-Control
make -C lib/libnx -j8
make -C lib/libnx install
make dist -j8
python3 scripts/verify-package.py dist/MissionControl-0.16.1.zip
```

Нужен devkitPro/devkitA64 и пакет `switch-libjpeg-turbo`. Используйте
закреплённые коммиты обоих submodule. Установленная версия libnx может
не содержать новых Bluetooth-типов из закреплённого libnx; сборка и установка
этой зависимости решают проблему. Для изоляции можно собирать в Docker
`devkitpro/devkita64:latest`, как в workflow.

## Проверка

Обработчик из скомпилированного release ELF проверен выполнением AArch64-кода
через Unicorn: 271 сценарий, все идентификаторы команд, чтение цвета и
калибровочных диапазонов, сохранение ответов и обновление кнопок/стиков.
Проверка архива дополнительно сверяет исполняемый модуль с локальной сборкой,
его TID, конфигурацию MITM, патчи IPS32, версию и целостность ZIP.
Эти проверки не заменяют проверку работы контроллеров на консоли.
